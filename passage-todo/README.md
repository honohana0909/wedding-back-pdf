# PASSAGE — 当日のバック業務ToDo

結婚式場のバック担当が、コース・追加条件・進行時刻から当日のToDoを作り、印刷／PDF保存する静的Webアプリです。アップロードされた「バック業務確認チェックリスト.xlsx」の「業務確認チェックリスト」52項目を収録しています。

## 起動方法

最も簡単な方法は、このフォルダーの **index.htmlをSafariやChromeで開く**ことです。同じフォルダーのJavaScript・CSSも必要なので、index.htmlだけを移動しないでください。ビルドやライブラリーのインストールは不要です。

ブラウザーのローカルファイル制限で保存できない場合は、このフォルダーで次を実行します（Python 3が必要）。

```sh
python3 -m http.server 4173 --bind 127.0.0.1
```

その後、[ローカルページ](http://127.0.0.1:4173)を開きます。終了はターミナルで `Ctrl+C`。Node.jsがある場合は `npm start` でも同じ起動ができます。ポートが使用中なら4173を別の番号に変更してください。

## 使い方

1. 婚礼名・日付・会場・バック担当を入力します。
2. 洋コース／和洋会席を選び、当日の条件にチェックします。
3. 決まっている主要進行時刻を入力します。未入力の時刻は空欄のまま保持します。
4. 自動生成されたToDoを「進行順」「時刻順」で確認します。「確認事項あり」で未確定事項を絞り込めます。
5. 各項目の「編集」で、ToDo本文・手動開始時刻・手動期限時刻・当日のメモ・PDF掲載を変更できます。元の開始／期限の文言は残ります。
6. 「＋ ToDoを追加」から独自の作業を追加します。独自ToDoはコースを切り替えても残ります。削除は独自ToDoの編集画面から行います。
7. 完了した項目をチェックします。条件を外した項目も編集内容やチェックを保持し、条件を戻すと復元します。
8. 「印刷・PDF保存」を押します。印刷画面でA4縦を選び、必要に応じて送信先を「PDFに保存」（macOSはPDFメニュー）にします。ブラウザーのヘッダー／フッターをオフにするとURL等を省けます。

印刷は画面の絞り込みや詳細欄の開閉に依存しません。対象ToDoの必要物・連携先・場所・注意点・修正内容・当日のメモも掲載します。チェック済みの項目も含みます。

## 対応する条件

洋コース／和洋会席と、尾鰭椀・デザートビュッフェ・ローストビーフ・天ぷら・子ランチ・子バーグ・子コース・イベント／余興を組み合わせられます。

子ランチ／子バーグ／子コースの数量確認は選択した種類のみ生成します。「子供料理を1Fに上げる」「対象卓・席を確認する」は子ども料理が一つ以上あるときに1件ずつ生成します。オプションの実施有無確認も、そのオプションを選んだ場合に含まれます。

## 時刻と並び順のルール

- **基準時刻と作業時刻を区別**します。開場12:00に対する「開場後」は、12:00を基準として表示します。「12:00に作業を実施する」と自動確定するものではありません。前後の文言を必ず併記します。
- **所要時間を推測しません。** 「10分前」「15分後」などの固定分数は使いません。
- **提供開始と提供完了を区別**します。HOV提供後・スープ提供後・ポアソン提供後は対応する「提供完了」の入力を参照します。完了時刻が空欄なら開始時刻で代用しません。
- **作業依存の条件を残します。** 「2Fから受取後」「前菜を1Fへ上げた後」などは、開始時刻に置換しません。期限や関連進行を表示上の目安にします。
- **進行順**は出勤、MTG、先付け、開場、各料理などの参照順です。同じ進行は原票の「前→時点→後」、同条件では原票の行順です。オプションの実際の順序は婚礼ごとに異なるため、当日の時計順を見たい場合は時刻順を選びます。
- **時刻順**は手動開始時刻／開始基準時刻を優先し、それがない場合は手動期限時刻／期限基準時刻を使用します。どちらもない項目は末尾です。同時刻は進行順・前後関係・原票行順で安定して並べます。
- 手動時刻は進行時刻を変更しても上書きしません。編集で手動時刻を空欄にすると基準時刻に戻ります。
- 時刻は同日内の24時間表記です。日またぎには対応しません。開始基準が期限基準を超える項目は警告します。進行シミュレーションや作業完了による進行停止はありません。

## Excelを優先するための取り扱い

会話中の古い表ではなく、アップロードされたExcelの表示文字列を採用しています。Excelのふりがなデータは本文ではないため除外しています。表記は原票に合わせ「ペストリー」「料理担当」です。原票にない作業は追加していません。

| 原票の状態 | アプリの扱い |
| --- | --- |
| 確認状態「確定」 | 「原票：確定」と表示。時刻の矛盾等とは分ける |
| 確認状態「要確認」「修正」または空欄 | 確認事項として表示。勝手に確定しない |
| PDF掲載「○」 | 掲載 |
| PDF掲載「△」 | 補足と明示して掲載 |
| PDF掲載「×」 | 印刷対象から除外。画面には表示 |
| PDF掲載が空欄 | 「PDF：未指定」と表示。初期設定では要確認として印刷する。印刷設定で一括除外、または個別編集で掲載を指定できる |

原票で注意が必要な箇所：

- **19・21・22・23・45行目**：PDF掲載が空欄。○に書き換えていません。
- **45行目**：「子供料理を1Fに上げる」の確認状態が空欄。
- **36行目**：開始「披露宴開始後〜デザート前」に対し期限「開場前」。両方を保持して前後関係の要確認を表示します。
- **53行目**：開始「イベント開始前」に対し期限「開場前」。両方を保持して前後関係の要確認を表示します。
- 同名の「パンを1Fへ上げる」はHOV提供後とスープ提供後で別作業として保持します。和洋会席のちらし寿司運搬2行も統合していません。

元の本文や確認状態は `checklist.js` に残ります。利用者の変更は別の保存領域です。本文変更時は画面の詳細欄から元のToDoも見られます。

## 保存について

入力内容・独自ToDo・編集・完了チェック・並び順・印刷設定をブラウザーのlocalStorageに保存します。保存対象は現在の婚礼1件です。別の婚礼を始めるときは「元データと保存について」内の「入力を消去して新しい婚礼を作る」を使用します。消去前に確認画面を表示します。

保存先は利用中のブラウザーとURLごとに分かれます。ローカルファイル、localhost、GitHub Pagesの間で保存内容は引き継がれません。プライベートブラウズやブラウザーデータ消去で保存内容が失われることがあります。保存エラー時は画面に表示します。

ログイン、クラウドDB、複数端末同期、外部送信、解析ツール、外部CDNは使用していません。入力情報はGitHubリポジトリへ書き込まれません。

## GitHub Pagesへの公開方法

公開先リポジトリが未指定のため、今回の成果物はローカルに作成しています。GitHubへのアップロード・公開はまだ行っていません。

1. GitHubで公開用リポジトリを作成します。
2. **このpassage-todoフォルダーの中身**をリポジトリの直下へアップロードします。最低限 `index.html`、`styles.css`、`checklist.js`、`engine.js`、`app.js`、`.nojekyll`、`README.md` を含めます。フォルダー自体を一段深く置かないでください。
3. リポジトリの **Settings → Pages → Build and deployment** を開きます。
4. Sourceで **Deploy from a branch**、Branchで **main**、フォルダーで **/(root)** を選び、Saveを押します。
5. 公開処理完了後、Pagesに表示されるURLを開きます。通常は `https://<ユーザー名>.github.io/<リポジトリ名>/` です。
6. コース切り替え、独自ToDo追加、再読み込み後の保存、印刷画面を確認します。

ビルド処理やGitHub Actionsの独自設定は不要です。参照パスはすべて相対パスなのでリポジトリ名に依存しません。

公開方法の根拠：[GitHub公式・公開元の設定](https://docs.github.com/en/pages/getting-started-with-github-pages/configuring-a-publishing-source-for-your-github-pages-site)。

## 主要変更点・ファイル構成

今回の要件に合わせ、このフォルダーに新しい静的アプリを作成しました。ホーム直下の既存 `wedding-back-app` および旧デモは変更していません。

| ファイル | 役割 |
| --- | --- |
| index.html | 条件・時刻入力、ToDo一覧、編集画面 |
| styles.css | PC／スマートフォン向け画面、A4印刷用レイアウト |
| checklist.js | Excelの52項目。元の空欄や確認状態を保持 |
| engine.js | 条件選択、進行との対応、整列、確認事項、保存データ検証 |
| app.js | 簡易編集、独自ToDo、保存、印刷対象の生成 |
| scripts/extract_checklist.py | 今回のExcelから表示文字列を抽出する開発用処理 |
| tests/engine.test.js | 条件・時刻・保存・PDF掲載ルールのテスト |

業務データを更新する際は、Excelの変更と `checklist.js`、`engine.js` の行番号対応を照合してください。抽出スクリプトは今回のExcel構造専用です。行の挿入や削除があった場合、抽出だけでは進行対応を更新できません。Webページ内でExcelを再アップロードする機能はありません。

## 検証

Node.jsがある環境では、依存パッケージのインストールなしで実行できます。

```sh
npm test
```

自動テストは2コース×8条件の全512組み合わせ、原票の空欄・変更内容、時刻未入力、提供開始／完了、運搬依存の文言・順序、手動時刻・メモ・完了チェックの保持、並び替え、PDF掲載、独自ToDo、保存形式の検証を含みます。

画面・印刷に関する実施結果は [検証記録](docs/verification.md) に記載します。業務上の未確定事項を自動テストによって確定したことにはしていません。
